# 백엔드 인수인계서 - PDF 기반 AI 질문 채팅 오류

## 1. 문서 목적

- FastAPI/React/Spring Boot 흐름 분석 기준으로 작성함.
- PDF 상세 화면의 AI 질문 채팅에서 PDF 내용 기반 답변이 나오지 않는 문제 중 백엔드에서 조치해야 할 내용을 정리함.
- 실제 Spring Boot 코드는 수정하지 않았음.
- 실제 확인한 파일 기준:
  - frontend/src/pages/ArchiveDetail.jsx
  - frontend/src/services/api.js
  - backend/src/main/java/com/studybridge/api/controller/MaterialController.java
  - backend/src/main/java/com/studybridge/api/service/AiIntegrationService.java
  - backend/src/main/java/com/studybridge/api/service/PdfExtractionService.java
  - backend/src/main/java/com/studybridge/api/dto/QuestionDTO.java
  - backend/src/main/resources/application.yml
  - fastapi/main.py
  - fastapi/image_pdf_pipeline.py
- 확인되지 않은 Spring Boot 수정 위치 또는 정책은 “확인 필요”로 표시함.

## 2. 현재 문제 요약

- 사용자가 PDF 상세 화면에서 “이 pdf 요약 해줘”, “PDF의 내용을 읽고 이에 대한 내용을 요약해줘”를 입력했을 때 실제 PDF 내용 기반 답변이 나오지 않음.
- 응답 문구 “문서 내용만으로는 명확히 확인하기 어렵습니다.”는 FastAPI /api/ai/question 프롬프트에 포함된 fallback 지시 문구와 일치함.
- 백엔드 현재 흐름은 Material.extractedText를 FastAPI /api/ai/question의 text 필드로 전달하는 구조임.
- 따라서 FastAPI가 호출되더라도 material.getExtractedText()가 비어 있거나 이미지 PDF에서 의미 있는 텍스트가 추출되지 않으면 해당 fallback 답변이 나올 수 있음.
- F12 Network에 요청이 보이지 않는 문제는 프론트 이벤트/브라우저 필터/인증 리다이렉트/개발 환경 확인 필요이며, 백엔드 로그로 실제 요청 도달 여부 확인 필요.

## 3. 백엔드 관련 원인 후보

### 3-1. material_id로 Material 조회 여부

확인 결과:
- MaterialController.java에 POST /api/materials/{materialId}/question 존재함.
- AiIntegrationService.askQuestion(Long userId, Long materialId, QuestionDTO.Request request)에서 getMaterialSafely(userId, materialId)를 호출함.
- Material 조회 및 사용자 권한 검증은 getMaterialSafely 내부 구현 기준으로 동작하는 것으로 보임.

확인 필요:
- getMaterialSafely가 materialId와 userId를 정확히 검증하는지 상세 구현 확인 필요.

### 3-2. extractedText 존재 여부

확인 결과:
- Material 엔티티에 extractedText 필드가 있음.
- MaterialDTO에도 extractedText 필드가 있음.
- AiIntegrationService.askQuestion()는 material.getExtractedText()가 null 또는 blank이면 IllegalArgumentException을 발생시킴.

문제 가능성:
- extractedText가 빈 문자열이 아닌 짧은 텍스트, 깨진 텍스트, 이미지 PDF에서 추출된 무의미한 텍스트이면 FastAPI 검증을 통과하지만 답변 근거로 부족할 수 있음.
- 이 경우 FastAPI가 “문서 내용만으로는 명확히 확인하기 어렵습니다.” 계열 답변을 생성할 수 있음.

### 3-3. PDF 텍스트 추출 여부

확인 결과:
- PdfExtractionService.sendToFastApiForExtraction()가 업로드 PDF를 FastAPI로 전달함.
- application.yml 기준 external-api.fastapi.url 기본값은 http://localhost:8000/api/extract임.
- FastAPI /api/extract는 PyMuPDF page.get_text()로 일반 텍스트만 추출함.

문제 가능성:
- 이미지로만 구성된 PDF는 /api/extract에서 추출 텍스트가 거의 없을 수 있음.
- PdfExtractionService는 extracted_text 값을 그대로 Material.extractedText에 저장함.
- extracted_text 품질 검증 또는 최소 길이 검증은 현재 PdfExtractionService 코드에서 확인되지 않음.

### 3-4. 이미지 PDF Vision 추출 여부

확인 결과:
- FastAPI에는 image_pdf_pipeline.py와 다음 API가 존재함.
  - POST /api/ai/pdf/extract-vision-text
  - POST /api/ai/pdf/extract-vision-text/upload
- 하지만 Spring Boot PdfExtractionService는 현재 external-api.fastapi.url 설정값을 사용하여 /api/extract로 전송함.
- Spring Boot가 Vision 추출 API를 호출하는 코드는 현재 확인되지 않음.

문제 가능성:
- 이미지 PDF에서 일반 텍스트 추출이 실패해도 Vision 추출 API로 재시도하지 않음.
- 그 결과 extractedText가 비거나 의미 부족한 상태로 질문 API까지 전달될 수 있음.

### 3-5. FastAPI로 pdf_text 전달 여부

현재 질문 API 흐름:
- Spring Boot → FastAPI: POST /api/ai/question
- payload:
  - text: material.getExtractedText()
  - question: request.getUserQuestion()

확인 결과:
- 현재 FastAPI /api/ai/question은 text와 question을 받음.
- 별도 POST /api/ai/material-question 엔드포인트는 현재 확인되지 않음.

주의:
- 로드맵 API의 pdf_text 필드와 질문 API의 text 필드는 서로 다름.
- 질문 API는 현재 text 필드에 PDF 내용을 넣어야 정상 동작함.

### 3-6. FastAPI 응답 필드 매핑 여부

확인 결과:
- FastAPI /api/ai/question 응답은 { "answer": "..." } 구조임.
- AiIntegrationService.askQuestion()는 response.containsKey("answer")이면 aiAnswer에 매핑함.
- MaterialQuestion 엔티티로 userQuestion, aiAnswer를 저장함.
- QuestionDTO.Response는 questionId, materialId, userQuestion, aiAnswer, createdAt을 반환함.
- 프론트 ArchiveDetail.jsx는 res.aiAnswer를 화면에 표시함.

필드 매핑 자체는 현재 코드 기준 일치함.

## 4. 백엔드 조치 사항

- React에서 material_id와 message를 받아야 함.
- 현재 React는 POST /api/materials/{materialId}/question로 { userQuestion }을 전송함.
- MaterialController는 해당 요청을 AiIntegrationService.askQuestion()으로 전달함.
- Material 조회 후 extractedText 확보 필요.
- extractedText가 null/blank인 경우 현재 예외를 던지지만, 프론트에 표시할 명확한 에러 응답 정책 확인 필요.
- extractedText가 너무 짧거나 의미 없는 경우도 실패로 판단하는 품질 검증 필요.
- 일반 PDF 텍스트 추출 실패 시 FastAPI Vision 추출 API 호출 필요.
- 이미지 PDF는 /api/extract만으로 충분하지 않으므로 /api/ai/pdf/extract-vision-text/upload 연동 필요.
- FastAPI 질문 API 호출 시 PDF 내용이 반드시 text 또는 신규 API의 pdf_text로 포함되어야 함.
- pdf_text/text 없이 FastAPI를 호출하면 안 됨.
- FastAPI 응답 answer를 aiAnswer로 매핑하여 React에 반환해야 함.
- 필요 시 MaterialQuestion에 질문/답변 기록 저장 유지.
- 로그 추가 권장:
  - materialId
  - extractedText null 여부
  - extractedText 길이
  - FastAPI 호출 URL
  - FastAPI 응답 status
  - FastAPI answer 길이

## 5. 권장 API 구조

### React → Spring Boot

현재 확인된 실제 경로:

POST /api/materials/{materialId}/question

Request:

{
  "userQuestion": "이 PDF 요약해줘"
}

권장 신규 또는 래핑 경로:

POST /api/materials/{materialId}/ai-question

Request:

{
  "message": "이 PDF 요약해줘"
}

주의:
- 현재 실제 코드는 userQuestion 필드임.
- message 필드로 변경하려면 DTO와 프론트 동시 변경 필요.

### Spring Boot → FastAPI 현재 구조

POST /api/ai/question

Request:

{
  "text": "Material.extractedText",
  "question": "이 PDF 요약해줘"
}

Response:

{
  "answer": "PDF 내용을 기반으로 생성한 답변"
}

### Spring Boot → FastAPI 권장 문서 질문 API

현재 FastAPI에는 아래 엔드포인트가 확인되지 않음. 필요 시 FastAPI 담당자와 합의 후 추가 가능.

POST /api/ai/material-question

Request:

{
  "material_id": 12,
  "message": "이 PDF 요약해줘",
  "pdf_text": "PDF에서 추출된 텍스트",
  "user_goal": "자료 기반 질문 답변"
}

Response:

{
  "status": "success",
  "material_id": 12,
  "answer": "PDF 내용을 기반으로 생성한 답변"
}

## 6. 이미지 PDF 처리 필요 사항

- 현재 FastAPI /api/extract는 PyMuPDF page.get_text() 기반 일반 텍스트 추출임.
- 이미지 PDF에서는 /api/extract 결과가 비거나 짧을 수 있음.
- FastAPI Vision 추출 API가 이미 존재함.
  - POST /api/ai/pdf/extract-vision-text/upload
  - POST /api/ai/pdf/extract-vision-text
- Spring Boot는 extractedText가 비었거나 최소 길이 미달이면 Vision 추출 API를 호출하는 보완 흐름 필요.
- Vision 추출 응답의 extracted_text를 Material.extractedText에 저장한 뒤 질문/요약/로드맵 생성에 사용해야 함.
- image_hash는 현재 PdfExtractionService에서 계산하지만, 이번 문제의 핵심은 image_hash 조회가 아니라 PDF 페이지 이미지 렌더링 및 Vision 분석임.

## 7. 예외 처리 기준

Spring Boot에서 처리해야 할 FastAPI/내부 오류:
- 400: text/pdf_text/message/question 비어 있음, PDF 경로/파일 검증 실패
- 404: PDF 파일 없음 또는 Material 없음
- 422: FastAPI Pydantic 검증 실패
- 500: OpenAI API Key 없음, Vision 분석 실패, FastAPI 내부 오류

권장 처리:
- extractedText 없음: “PDF 텍스트 추출이 완료되지 않았습니다. 잠시 후 다시 시도하거나 Vision 분석이 필요합니다.” 등 명확한 메시지 반환.
- extractedText 너무 짧음: 이미지 PDF 가능성으로 보고 Vision 추출 시도.
- FastAPI 호출 실패: 프론트에 일반 fallback 답변이 아니라 실패 상태를 반환.
- FastAPI가 “문서 내용만으로는 명확히 확인하기 어렵습니다.”를 반환한 경우: extractedText 길이와 내용 품질 로그 확인.

실제 백엔드 코드는 수정하지 않았음.

수정 후보:
- backend/src/main/java/com/studybridge/api/service/AiIntegrationService.java
  - askQuestion()에서 extractedText 길이/품질 검증 추가
  - FastAPI 호출 전 payload 로그 추가
  - 필요 시 /api/ai/material-question 또는 기존 /api/ai/question 호출 정책 정리
- backend/src/main/java/com/studybridge/api/service/PdfExtractionService.java
  - /api/extract 결과가 부족할 때 Vision 추출 API 호출
  - extractedText 저장 전 null/blank/길이 검증
  - Vision API 호출용 multipart payload 구성
- backend/src/main/java/com/studybridge/api/controller/MaterialController.java
  - 질문 API 응답/예외 메시지 정책 보완
- backend/src/main/java/com/studybridge/api/dto/QuestionDTO.java
  - 현재 Request는 userQuestion만 있음. message로 바꿀 경우 프론트와 동시 변경 필요.
- backend/src/main/resources/application.yml
  - FASTAPI_EXTRACTION_URL이 /api/extract만 가리킴.
  - Vision 추출 API URL 설정 추가 여부 확인 필요.

## 9. 테스트 기준

### 백엔드 테스트

- Spring Boot 로그에 material_id 출력.
- Material 조회 성공 확인.
- material.getExtractedText() null 여부 출력.
- material.getExtractedText().length() 출력.
- FastAPI 호출 payload에 text 또는 pdf_text 포함 확인.
- FastAPI 응답 answer 매핑 확인.
- MaterialQuestion 저장 확인.

### FastAPI 연동 테스트

현재 실제 FastAPI 질문 API:

curl -X POST "http://localhost:8000/api/ai/question" \
  -H "Content-Type: application/json" \
  -d '{
    "text": "PDF에서 추출된 실제 텍스트",
    "question": "이 PDF 요약해줘"
  }'

이미지 PDF Vision 추출 테스트:

curl -X POST "http://localhost:8000/api/ai/pdf/extract-vision-text/upload" \
  -F "material_id=12" \
  -F "user_goal=자료 기반 질문 답변" \
  -F "file=@lecture.pdf"

## 11. 결론

현재 백엔드 질문 흐름은 Material.extractedText를 FastAPI /api/ai/question의 text로 전달함.
응답 문구는 FastAPI 문서 기반 질문 프롬프트의 fallback 지시와 일치함.
핵심 원인은 extractedText가 비어 있거나 이미지 PDF에서 의미 있는 텍스트가 확보되지 않는 흐름일 가능성이 큼.
이미지 PDF는 /api/extract가 아니라 Vision 추출 API 연동이 필요함.
이번 작업에서 Spring Boot 코드는 수정하지 않았음.
