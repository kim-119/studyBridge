# StudyMate 품질·UX 개선 설계 (기본개념모드)

날짜: 2026-06-23
브랜치: LLM-clean

## 배경 / 문제

기본개념모드(멀티에이전트) 대화에서:
1. 답변이 짧고 예시·개념 정리가 부족하다. token 한도는 넉넉한데(BACHELOR=1600…) 프롬프트가 구조/예시를 강제하지 않는다.
2. "더 깊이 자세히 설명해줘" 같은 후속발화가 오히려 1~2문장으로 짧아진다 — 후속발화가 `basic_contextual_turn`(90~160 tok, 1~2문장)으로 강제 라우팅되고, "심화 요청" 액트가 없기 때문.
3. 반박/한줄정리 말풍선에 마크다운 마커(`> 💬 *...*`)가 날것의 `*`/`>`로 보인다.
4. 반박 내용이 어디를·왜·어떻게 틀렸고 무엇이 맞는지 구조가 없다.
5. 한 줄 정리(WRAP)가 매 턴 자동으로 붙는다.
6. 마인드맵이 전 히스토리를 role별 최신 1개로 뭉개 "마지막 채팅 고정"처럼 보인다.
7. 마인드맵 간선이 상호작용 유형(반박/예시/보충/피드백/정리)을 시각적으로 구분하지 못한다.

## 결정 사항 (사용자 확인됨)

- 지식 보강: **한국어 위키피디아 강화 + Tavily 웹검색** (신규 키 불필요; 네이버 지식백과 키 없음).
- 답변 깊이: **개념 → 예시 → 정리 구조(중간 깊이)**.
- 마인드맵: **선택한 질문 턴 기준** (이전 턴 되돌아보기 가능, 기본=최신).
- 한 줄 정리: **사용자가 요청할 때만**, 요청 시 **깔끔하고 상세한 구조화 정리**.

## 범위

### A. 답변 품질/깊이 (백엔드 `fastapi`)

A1. **구조 강제** — `_build_single_agent_system_prompt` + user 지시문에 "핵심 개념 설명 → 구체 예시 1개 → 한 줄 핵심 정리" 골격을 페르소나 톤 유지한 채 요구. (각 교수 답변 끝의 짧은 개념 요약 문장은 유지. 별도 🧩 정리 발화와 무관.)

A2. **지식 보강 모듈** `app/services/knowledge_enrichment.py` (신규)
  - `build_knowledge_context(query) -> str`: 한국어 위키(다중 문서, 인트로→본문 일부 ~1200자) + Tavily 웹검색(키 있을 때, 짧은 timeout·관련성 필터)을 단일 "[참고자료]" 블록으로 합침.
  - graceful: Tavily 키 없음/실패 → 위키만; 위키도 없음 → 빈 문자열.
  - 턴당 1회 fetch(기존 `_fetch_wikipedia_context` 호출 지점 2곳을 대체), 메모리 캐시, 외부 호출 timeout 3s.
  - 하드코딩 주제어 금지(content-free): 특정 도메인 단어를 로직/폴백에 박지 않음.

A3. **"더 자세히/더 깊이" 후속발화 수정**
  - `dialogue_act_classifier.py`에 `FOLLOWUP_DEEPEN` 액트 추가. 트리거(결정론+LLM rule): "더 자세히", "더 깊이", "자세히 설명", "구체적으로", "더 설명". `answer_depth='full'`.
  - 라우팅: DEEPEN이면 1~2문장 contextual turn으로 보내지 않고, **직전 답변을 맥락으로 둔 전체 답변 경로**(A1 구조 + A2 보강)로 보냄.

### B. 마인드맵 = 선택한 질문 턴 기준 (프론트)

- `chatHistory`를 `parentId`(USER 질문 → 그 자식 AI 답변들)로 **턴 그룹핑**.
- 마인드맵 상단에 **질문 턴 선택기**(기본=최신 턴, 이전 턴 선택 가능).
- `buildGraph`에 선택 턴의 질문+답변 메시지만 전달. role별 최신 1개로 전 히스토리를 뭉개던 로직 제거.

### C. 반박/정리 텍스트 전처리 + 배지 (프론트 + 백엔드)

- 프론트(`onAgentAnswer`): content에 `> 💬 *...*` / `> 🧩 *...*` 마크다운을 **주입하지 않음**. 깨끗한 본문만 저장.
- 말풍선에 `msg.actType` 기반 **스타일 배지** 렌더: REACTION → "💬 보충·반박 → {대상}", WRAP → "🧩 정리". 잔여 `*`/`>` 마커 정리.
- 백엔드 **반박(REACTION) 구조화** (`_generate_round2_feedback` 프롬프트): ① 어느 지점(내용 중심 지칭, 이름표 금지) ② 무엇이 부족/틀렸나+왜 ③ 올바른/보완 설명(어떻게 맞나) ④ 근거 또는 구체 예시 1개. 페르소나 톤 유지·인신공격 금지·반복 금지.

### WRAP(정리) 온디맨드 (백엔드)

- `plan_discussion`이 매 턴 끝 WRAP를 **자동 생성하던 것 제거** → 기본 턴 = `직접답변 + 반박`만.
- 사용자가 "정리/요약/3줄/핵심만" 등 요청(이미 '3줄 요약' 칩 존재) → **정리 인텐트 감지** → 그때만 🧩 정리 발화.
- 요청 시 정리는 **깔끔+상세 구조**: 핵심 개념 정리 / 오개념·주의점 / 복습 포인트.

### D. 마인드맵 간선 시각 부각 (프론트)

- 답변 메시지의 `actType`/`replyTo`로 **교수 간 간선 직접 도출**(REACTION→반박·보충, WRAP→정리) + 기존 interactions.
- `RELATION_STYLE` 확장: 반박/예시/보충/피드백/정리/답변 별 색·선 스타일(점선/실선)·화살표·라벨 구분.

## 데이터 흐름

질문 → (백엔드) knowledge_enrichment 턴당 1회 → 플래너(직접답변+반박, WRAP은 요청시) → 각 발화 SSE(actType/replyTo/displayOrder) → (프론트) displayOrder 정렬·배지 렌더 → 마인드맵은 선택 턴의 메시지(actType/replyTo)로 노드·간선 구성.

## 비목표 (YAGNI)

- 네이버 지식백과 연동(키 없음).
- 발화 순서/displayOrder 정렬 변경(이미 완료).
- 토론/소크라테스/상황극 모드 변경.
- 마인드맵 세션 전체 누적 뷰.

## 테스트

- 백엔드: knowledge_enrichment(키 없음→위키만/없음→빈값, 캐시, timeout), FOLLOWUP_DEEPEN 분류·full 라우팅, 반박 구조 프롬프트, WRAP 온디맨드(요청 없을 때 미생성/요청 시 생성). pytest, 실 qwen3 스모크.
- 프론트: `npm run build` 통과. 턴 그룹핑/선택기, 배지 렌더(`*` 미노출), 간선 스타일.

## 배포

- A·반박·WRAP = fastapi CD (fastapi/** 변경).
- B·C(프론트)·D = frontend CD.
- 둘 다 LLM-clean push → CD 자동배포(인증서 이슈 해소됨).
